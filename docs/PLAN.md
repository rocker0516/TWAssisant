## 1. 專案目標

| # | 目標 | 對應階段 |
|---|---|---|
| 1 | 台股資訊統整網頁 | 階段 1A / 1B |
| 2 | 台股推薦功能 | 階段 2 |
| 3 | 推薦分兩種方式：**規則型**（資料分析找條件）、**ML 模型**（特徵工程 + 訓練） | 階段 2A / 2B |
| 4 | 推薦成熟後，用 RL agent 全自動交易 | 階段 3 / 4 |

**一句話說明**：每天收盤後，系統自動抓資料、算指標、幫每檔股票打分數，網頁顯示推薦清單；最終由 RL agent 根據推薦決定隔天的買賣，透過富果下單。

## 3. 每日運作流程

```
 14:30 收盤
   │
   ▼
 ① 抓資料      FinMind（股價、籌碼、基本面、新聞）、MOPS 重大訊息、PTT、國際行情
   ▼
 ② 清洗檢核    缺值、異常價格、除權息調整
   ▼
 ③ 文字分析    LLM：對應股票、情緒、事件分類（1B）
   ▼
 ④ 算特徵      只用「決策當下已公布」的資料
   │
   ├──▶ ⑤a 規則篩選 ─┐
   └──▶ ⑤b ML 模型  ─┴──▶ ⑥ 推薦清單（分數 + 理由）──▶ 網頁
                                   │
                                   ▼
                         ⑦ RL 決定部位（階段 4）
                                   ▼
                         ⑧ 風控檢查（硬性規則，AI 不可覆寫）
                                   ▼
 隔日 09:00 前  ⑨ 富果下單 → 盤後對帳 → 績效紀錄
```

## 4. 資料版圖

| 類別 | 內容 | 來源 | 階段 |
|---|---|---|---|
| 技術面 | 日 K、成交量、還原權值股價 | FinMind | 1A |
| 籌碼面 | 三大法人、融資融券、借券、分點券商、集保股權分散 | FinMind | 1A |
| 基本面 | 月營收、財報（損益/資產負債/現金流）、股利 | FinMind | 1A |
| 國際總經 | 美股指數、費半、台積電 ADR、匯率、台指期夜盤 | FinMind / yfinance | 1A |
| 事件 | 重大訊息、法說會、增資、庫藏股、處置股 | MOPS / FinMind | 1A |
| 新聞 | 財經新聞標題與摘要 | FinMind 新聞資料集 | 1B |
| 社群 | PTT Stock 版文章與推文 | PTT 爬蟲 | 1B |

**時間原則**：每一筆資料都記錄「**公布時間**」，不只記錄「所屬期間」。
例如：6 月營收的所屬期間是 6 月，但公布時間是 7/10 → 7/10 收盤後才能使用。
13:30 之後發布的新聞或文章，只能影響**隔一個交易日**的決策。

## 5. 階段規劃

### 階段 1A：資料地基 + 資訊網頁
- **內容**：結構化資料（技術、籌碼、基本面、國際總經、重大訊息）每日自動抓取、檢核、入庫；網頁提供個股查詢
- **產出**：個股頁（K 線、法人進出、營收、財報、重大訊息）、每日更新狀態頁
- **完成標準**：
  - 每日排程自動完成，失敗時會通知
  - 上市櫃全部股票都可查詢
  - 資料檢核報告無重大異常

### 階段 1B：新聞與社群
- **內容**：新聞 + PTT 抓取、LLM 分析、標註系統、準確率監控
- **產出**：個股頁新增新聞（AI 摘要 + 正負面標記）、PTT 熱度趨勢；後台標註頁
- **完成標準**：LLM 準確率達到及格線（見第 7 節）

### 階段 2A：規則型推薦
- **內容**：資料分析 → 找出候選條件 → 回測驗證
- **產出**：規則庫、每條規則的回測報告、推薦頁
- **完成標準**：每條上線規則都有扣除成本後的回測（勝率、報酬、最大回撤、夏普值）

### 階段 2B：ML 模型推薦
- **內容**：特徵工程 → LightGBM 訓練 → walk-forward 驗證；文字特徵在此階段做實驗
- **產出**：模型、MLflow 實驗紀錄、特徵重要性報告
- **完成標準**：在樣本外年份表現穩定，且優於規則型

### 階段 3：回測整合 + 模擬盤
- **內容**：推薦結果用統一回測引擎評估 → 富果模擬環境實際運行
- **完成標準**：模擬盤連續運行至少 3 個月，表現與回測差距在可接受範圍內

### 階段 4：RL 自動交易
- **內容**：Gymnasium 交易環境 + Stable-Baselines3 agent；RL 決定持股檔數、資金配置、加減碼、停損
- **上線順序**：回測 → 模擬盤 → 小額實盤 → 逐步放大
- **完成標準**：小額實盤績效符合預期，風控機制實際觸發測試通過

## 7. LLM 分析驗證機制

### 7.1 四層驗證

| 層 | 做法 | 驗證什麼 |
|---|---|---|
| ① 考試 | 使用者標註 300 篇新聞 + 200 篇 PTT 當標準答案，與 LLM 比對 | 判斷是否和人一致 |
| ② 交代理由 | LLM 必須引用原文作為證據；程式自動檢查證據存在、股票代號正確；允許回答「無法判斷」 | 防止捏造、對錯股票 |
| ③ 定期抽查 | 每週隨機抽 20 篇複查；準確率下降就發警報；記錄模型與提示詞版本 | 上線後品質不衰退 |
| ④ 市場驗證 | 正面 / 中性 / 負面三組，比較之後 1～5 日的超額報酬 | 判斷是否真的有預測力 |

### 7.2 及格線

| 項目 | 目標 |
|---|---|
| 股票對應 | > 95% |
| 事件分類 | > 90% |
| 新聞情緒 | > 85% |
| PTT 看多 / 看空 | > 75% |

### 7.3 PTT 分層處理
- **熱度**（文章數、推文數、推噓比）：直接計算，不使用 LLM
- **立場**（看多 / 看空）：交給 LLM

### 7.4 流程
```
訂標註規則 → 使用者標註 500 篇 → 調整提示詞直到及格 → 上線（附證據 + 自動檢查）
→ 每週抽查 → 階段 2B 驗證預測力
```

## 9. 核心原則

1. **不偷看未來**：所有資料以「公布時間」為準；回測一律使用 walk-forward。
2. **成本一定要算**：買進手續費 0.1425%、賣出手續費 0.1425% + 證交稅 0.3%（當沖減半另計）；考慮漲跌停無法成交、T+2 交割。
3. **一套回測引擎**：規則、ML、RL 用同一把尺評分。
4. **一套券商介面**：回測、模擬、實盤只差一個設定。
5. **風控獨立於 AI**：硬性規則寫在 `trading/risk/`，任何策略都不能繞過。
   - 單檔部位上限（例：總資金 10%）
   - 單日虧損上限（例：2%，觸發即停止交易）
   - 單日下單金額 / 筆數上限
   - 緊急停止開關
6. **先證明有用再採用**：新資料、新特徵都要通過回測才能進入正式模型。

## 10. 多使用者與部署設計

### 10.1 系統切成兩半
```
┌──────── 公開網站（給所有使用者）────────┐   ┌──── 個人交易系統（只有擁有者）────┐
│ 個股資訊、新聞、PTT 熱度、篩選工具      │   │ RL、風控、富果下單、帳戶資料      │
│ 帳號登入、權限                          │   │ 不對外開放、不經過公開 API        │
└─────────────────────────────────────────┘   └───────────────────────────────────┘
                 └────────── 共用：資料庫（唯讀）、特徵、模型 ──────────┘
```
- 交易模組與公開網站是**不同服務**，公開網站的任何漏洞都碰不到下單功能
- 富果憑證只存在交易服務，不放在網站服務

### 10.2 角色
| 角色 | 權限 |
|---|---|
| 訪客 | 首頁、部分公開資訊 |
| 一般使用者 | 個股資訊、新聞、篩選工具、自選股 |
| 管理員（擁有者） | 標註後台、排程狀態、模型管理、交易系統 |

### 10.3 從家用機器到雲端
- 全部服務容器化（Docker Compose），搬家 = 複製設定 + 還原資料庫
- 所有設定、密碼放環境變數（`.env`，不進 git）
- 不寫死任何本機路徑
- 每日自動備份資料庫
- 家用階段的對外連線使用 Cloudflare Tunnel 或 Tailscale，**不在路由器開 port**

## 11. 法規與授權風險（正式開放前必須釐清）

> 以下為風險提示，非法律意見；開放給他人使用前，建議諮詢律師。

| 風險 | 說明 | 暫定做法 |
|---|---|---|
| 投顧業務 | 在台灣，對不特定人提供個股買賣建議，可能構成需要執照的「證券投資顧問業務」 | 對外以「資訊 + 使用者自訂條件的篩選工具」呈現；個股推薦先只給擁有者使用，待法律確認後再決定是否開放 |
| 代客操作 | 幫他人下單或管理他人資金屬於全權委託，需要執照 | 自動交易**只用於擁有者本人的帳戶** |
| FinMind 資料轉散布 | 個人付費方案未必允許把資料提供給其他使用者 | 開放前確認 FinMind 條款，必要時改用商業方案 |
| 新聞與 PTT 著作權 | 不可轉載全文 | 只顯示標題、連結、AI 摘要與統計數字 |
| 個資 | 使用者帳號屬個資 | 密碼雜湊儲存、最小化收集、提供刪除帳號功能 |
