# 回測實驗室＋使用者自訂軌 設計文件

2026-08-20 定案。方案 A：規則引擎＋即時計算＋小快取。

## 目標

讓使用者在策略室裡自訂篩選條件、自訂回測範圍與目標，驗證後把策略掛成
進場推薦的第三軌（波段軌、長線軌之外，名字隨策略名）。

## 決策紀錄（與使用者確認過）

| 問題 | 決定 |
|---|---|
| 條件形式 | 簡單／專業兩種模式，最終都編譯成同一份 AND 條件清單 |
| 簡單模式 | 策略模板＋預設閾值開關，可再用 AND 追加條件 |
| 目標定義 | N 日內碰 +X%（隔日高進場錨），可選停損：先碰 -Y% 算失敗 |
| 策略數量 | 多策略庫；同時只能啟用一個掛成第三軌 |
| 排序與上限 | 使用者挑排序欄位＋方向（預設成交金額降序）、每日取前 N 檔（預設 30） |
| 架構 | 方案 A：即時計算＋(策略,日期) 快取，不動盤後 pipeline |

## ① 資料模型

新表 `user_strategies`（帶 `user_id`，隔離做在 repository 層——呼應多租戶
阻擋點 2：純 ID 查詢即 IDOR）：

```
UserStrategy:
  id, user_id, name(使用者可改，即頁籤名), conditions(JSON),
  sort_field, sort_desc(bool), top_n(預設 30),
  target_pct(預設 10.0), horizon_days(預設 10), stop_pct(可 null＝不設停損),
  is_active(bool；同一 user 至多一個 true),
  created_at, updated_at
```

## ② 條件 schema 與欄位註冊表

`conditions = [{field, op, value}, ...]`，全部 AND。
`op ∈ {gt, lt, gte, lte, streak_gt, streak_lt}`（連 N 日型 op 的 value 是
`{n, threshold}`）。

欄位來自後端**欄位註冊表**（唯一真相，前端下拉直接吃它）：每欄定義
`key、label(中文)、group(技術/籌碼/基本面/市場)、unit、來源表、取值邏輯`。
首批約 20 欄：

- 技術：收盤價、成交金額、收盤/MA20-1(%)、收盤/MA60-1(%)、bias20、bias60、
  KD K 值、ATR%（atr14/close）
- 籌碼：外資 N 日累計買超、投信 N 日累計買超、大戶占比、大戶占比週變化、
  融資增減、借券餘額變化、當沖占比
- 基本面：月營收 YoY、月營收 MoM
- 市場：大盤 bias60（市場狀態濾網）

新增欄位只改後端註冊表一處。

## ③ 回測引擎

`POST /lab/strategies/{id}/backtest`，同步回傳（範圍上限 12 個月）。

- 範圍：起訖日；UI 提供 3／6／12 個月快捷鈕，也可自填。
- 口徑與波段軌 KPI 定版一致：訊號日收盤符合條件 → **隔日高進場錨** →
  `horizon_days` 內最高價碰到 `+target_pct%` 算命中；設了 `stop_pct` 時，
  先碰停損算失敗，**同日先後不可知一律保守記失敗**。
- 每個訊號日套排序＋top_n 後才計樣本（與每日清單口徑完全一致）。
- 回傳：總樣本、命中率、全市場同期基率（沿用現有基率算法當對照組）、
  lift、平均最深回撤、逐月分佈、最近 3 個訊號日明細。
- 防呆：單日候選 >200 檔提出「條件太鬆」警告；樣本 <30 顯示「樣本不足」
  徽章；結果面板明示回測期的大盤狀態（教訓：70% 命中率是行情產物）。

## ④ 進場推薦整合

- `is_active` 策略在推薦頁新增第三個頁籤，標題＝策略名。
- 內容＝最新交易日收盤資料跑規則、排序取前 N 檔；以 (策略 id＋條件雜湊,
  日期) 快取，當日重複開頁不重算，策略一改雜湊變即失效。
- 卡片顯示觸發條件摘要＋該策略最近一次回測命中率。
- 無啟用策略時頁籤不出現。

## ⑤ 權限

- 策略 CRUD 全走 user_id 隔離的 repository（建構子強制吃 user_id）。
- `routes_lab.py` 順手補 `prefix="/lab"`（多租戶阻擋點 3）。
- Free/Pro 分層先不做 gating，欄位預留（entitlement 註冊表落地後再接）。

## ⑥ 測試

- 規則求值器單元測試：每個 op × 代表性欄位、null 值處理。
- 回測口徑對照測試：以會噴成效引擎的已知結果當基準比對。
- Ownership 測試：A 用戶讀不到／改不到 B 用戶的策略。
- 快取失效測試：改條件後當日清單重算。

## 非目標（YAGNI）

- OR 群組、自由公式（第一版不做）
- 多個自訂軌同時掛推薦頁
- 「N 日後收盤報酬」等其他目標型態
- 盤後 pipeline 預算層（策略多了再考慮方案 B）
