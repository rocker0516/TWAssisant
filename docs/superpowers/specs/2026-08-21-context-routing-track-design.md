# 情境路由軌（第一階段：類股×訊號效力矩陣）設計

日期：2026-08-21
分支：feature/CreateNewLook
狀態：設計定案，待實作規劃

## 0. 一句話

建立一張「類股群 × 訊號家族 × 情境條件 → 20日超額報酬效力」的實證矩陣，
回答「哪個訊號在哪個類股生態有效」，作為未來情境路由推薦（第二階段）的地基。

## 1. 背景與生態位

現有推薦來源：波段軌（10日碰+10%）、長線軌（基本面分數）、標籤徽章、
ETF 成分事件、中性化類股強度。各訊號各自為政，沒有一個地方把「同一檔股票
被多個來源指向」的證據依類股生態整合。

新軌道的核心假設：**不同類股生態吃不同訊號**（電子吃動能與消息、金融吃
基本面與股息、循環股吃報價與籌碼），因此訊號效力必須分類股驗證，
再據此路由。

已付學費的邊界條件：
- 類股 lead-lag（A 類股預測 B 類股）已驗證是死路（0 組過檢定、穩定性
  形同擲硬幣），本設計**不做** lead-lag。
- 中性化類股強度是已驗證真因子，作為情境判斷原料；sec_ret20 已壞，不用。
- 10日70%命中率是行情產物，跨行情穩定的是超額報酬——故 KPI 採超額口徑。

## 2. 目標函數（KPI，定版）

**20 個交易日內對大盤的超額報酬**。

- 形式：二元命中——「20 日內超額報酬曾達 +X%」。
- 門檻 X 不手拍：由基率掃描定版（比照角落重挖的基率倍數搬移原則），
  先以 +8~10% 級距掃描基率後定案。
- 一把尺走全矩陣：所有類股、所有訊號家族用同一 KPI，跨格子可比較，
  路由加值可歸因。

## 3. 矩陣三維

```
【類股群】 × 【訊號家族】 × 【情境條件】 → lift、樣本數、檢定結果
```

### 3.1 類股群

- 沿用 sector_engine 既有類股分群。
- 加上手工維護的 5~10 條核心產業鏈（半導體上中下游、AI 伺服器、蘋概、
  航運、重電…）。DB 已有 `IndustryChainMember` 表，沿用擴充，不另建。
- 一檔股票可同時屬於類股群與多條鏈。

### 3.2 訊號家族

六大家族：動能、量能、籌碼、基本面動能、消息熱度、事件（ETF 納剔）。
第一版全部取自既有引擎/資料表，不新增外部資料源。

籌碼家族已定版展開（見 §5）；其餘家族在實作規劃時以同等粒度
（參數化模板 × 掃描格）展開。

### 3.3 情境條件（第一版只放兩個）

1. **市場狀態**：取自 market_regime。
2. **同期共振**：該股所屬鏈上相關類股群當期同步強/弱，以中性化類股
   強度計算。同期共振是「條件維度」，非 lead-lag 預測。

## 4. 產業鏈關係圖

- 靜態資料（`IndustryChainMember`）：鏈名、成員、上中下游角色。
  手工維護、進 git 可追溯。
- **鏈稽核機制**：某條鏈的格子在回測中系統性失效時，產出「鏈檢討報告」，
  第一檢討對象是成員判斷是否錯誤（如個股轉型），修正後重跑；
  不靜默淘汰。

## 5. 籌碼訊號庫 v2（定版粒度範例）

資料表：Institutional、Margin、ShareholdingDistribution、ShortLending、
DayTrading、InsiderHolding。

### 訊號工程三規則

1. **門檻不手拍**：N/K/X 為掃描格，切點由基率倍數定
   （類股內超額命中 ≥ 基率 × m）。
2. **連續值優先**：先算連續量（類股內百分位），挖掘時以分位桶離散化，
   避免人為斷崖。
3. **反向訊號同樣驗證**：排除濾網的 lift 一樣要過檢定。

## 6. 驗證紀律（全沿用既有規範）

- 挖掘前先跑特徵污染稽核（挖掘池 12 必修）。籌碼家族與量能/波動度
  高度相關，為重點稽核對象。
- 格子過關三條件：最低樣本數、基率倍數門檻、跨期穩定性
  （至少兩個不重疊時段方向一致）。
- 樣本不足的格子標「資料不足」，不硬給結論。
- 多重檢定校正：候選格子達數百個，依既有檢定紀律防偽陽性。
- **對照基準**：同一訊號不分類股的全市場 lift。
  格子價值 = 分類股後超出全市場的部分（= 路由加值的直接度量）。

## 7. 交付物（第一階段）

1. 後端：矩陣計算管線（訊號模板展開 → 污染稽核 → 掃描 → 檢定 → 矩陣表）。
2. 前端：矩陣可視化一頁（紅綠格 + lift + 樣本數 + 檢定標記）。
3. 鏈稽核報告機制。

## 8. 明確不做（第一階段）

- 不做 lead-lag。
- 不做路由引擎與每日推薦清單（第二階段，另開 spec）。
- 不新增外部資料源。
- 第一階段設計不預先綁死第二階段實作。

## 9. 失敗準則

矩陣挖完若**沒有任何格子顯著優於全市場基準**，結論為
「類股路由不加值」，第二階段不啟動。此為有價值的負結果，比照 lead-lag
記錄存檔。
