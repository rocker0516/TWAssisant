# Level 2.1 市值加權頂分位組合（cap-top tilt）

日期：2026-09-18
狀態：設計凍結（使用者核可「好」），dev 調參中
上游：Level 2 FRS §13 結案指向的新題；Step 0 診斷 = `scripts/level1_capweight_diag.py`

## 0. 假設與證據

M2 的教訓：同一份 l1_lgbm_v2 排名，**聚合權重決定生死**——等權 Top-20 對市值
加權指數結構性落後（等權 U_t 零成本 dev −21.7pp／holdout −66.4pp）。

Step 0 診斷（凍結分數、零建模，dev/holdout 兩段）：
- 剔弱路線否決：弱分位市值佔比僅 5~8%，剔弱年化 +0.78%/+0.04%（t≈0）。
- **頂分位市值加權 vs 市值加權全體：dev +12.0%/年（t=+2.25）、
  holdout +15.5%/年（t=+1.72）**——跨兩個相反 regime 同向同量級。
- 市值加權 U_t 貼指數 TE ~1.5%/年（核心可行）；20 日再平衡年換手 6.9×
  （成本 ≈ 4%/年，逐日刷新分位口徑，實際持有衰減待模擬）。

「防禦型 edge（避弱>拉頂）」是**等權度量的敘事**；市值加權下活的是頂端訊號
（排名高的大型股）。與 Level 1 結論不矛盾，是同一排名的不同切片。

## 1. 組合定義（captop_v0）

```
eligible_t = { i ∈ U_t : pct5_t(i) ≥ THRESHOLD }
target_t   = eligible_t 依市值取前 TOP_N 檔
w_t(i)     = cap_t(i) / Σ cap_t(target_t)          （市值加權）
```

- 每 REBALANCE_EVERY 個交易日再平衡到目標權重（含加減碼，非只進出）。
- **微量單免疫**：|Δ部位| < MIN_TRADE（元）不下單——100 萬帳戶、20 元低消
  下，微調單成本佔比失控，這是結構參數不是調參對象。
- 無防禦規則（Step 0 已證弱分位對市值組合無肉；砍掉=少一個雜訊源）。
- 執行/成本/成交語意 100% 沿用 Level 2 引擎（FRS §3/§4，MOO、漲跌停、低消）。

## 2. dev 允許調的結構參數（只有三個軸）

| 軸 | 候選 | 理由 |
|---|---|---|
| THRESHOLD | 0.7 / 0.8 | 分位門檻：肉量 vs 容量 |
| REBALANCE_EVERY | 10 / 20 / 40 | 成本 vs 訊號衰減 |
| TOP_N | 15 / 30 | 集中度 vs 貼近度（低消可行性） |

MIN_TRADE = 10,000 元固定。KPI 與紀律同 FRS §6/§7：主 KPI=對加權指數超額＋
MDD ≤ 大盤；dev 調參 → 凍結 → holdout 一次性；附 vs 市值加權 U_t 歸因欄。

## 3. 已知限制（凍結前必須處理或文件化）

- **股本為現況快照**（company_profile 無歷史）：增減資造成權重二階誤差。
  dev/holdout 研究可接受；**上 live 前評估歷史股本回補**。

  但個別權重有誤差——結論以「方向與量級」解讀，不摳一位小數。
- 除權息偏差同 FRS §3（未還原 close vs 未含息指數，同向大致對稱）。
